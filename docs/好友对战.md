# 好友对战

在主菜单选择「好友对战」。一人创建房间，把6位房间号发给另一人；另一人输入房间号加入。双方准备后，各自完成主牌、初始团体及初始资源选择。无需注册；离线AI对局照常保留。

## 计时与设置

- 开局每项选择各60秒。双方可独立确认、重随；未确认的选择不会提前泄露。
- 每回合120秒。普通战斗和阴谋反制每次响应15秒，提交后交给对方，对方重新获得15秒；同一次响应内的分步目标、模式与费用选择共用剩余时间。
- 主回合计时在战斗期间暂停，返回主要阶段时继续原有余额。双方完成动画和桌面落点后，才开放下一操作并开始计时。
- 双方时间均显示为圆环。最后5秒变色并轻微脉动，最后3秒对正在操作的一方发出音效。音量为0时静音。
- 对战强制完整动画，设置中明确显示锁定状态；不会覆盖原有本地精简动画偏好。语言、音量和布局仅影响各自显示，不改规则、骰点、合法动作或时限。
- 查看大卡、查看战场、语言切换与设置窗口均不暂停在线思考时间，也不重置计时。

响应超时自动不再追加／放行；必要选择自动完成，回合超时自动结束。连续两个完整回合没有操作判负。断线暂停对局并自动重连，每人每局累计90秒宽限；重连不会重新补满宽限。离开已开始的房间视为认输。结果页仍可回看战场，双方均请求后在原房间重新开局。

## 服务端与信息

客户端通过 `wss://47.119.37.251/play` 连接服务器。服务端拥有唯一真实规则状态、共享牌堆及随机数；客户端只发送服务端签发的合法命令ID，不提交骰点、自己的计算结果或另一玩家身份。两个客户端都只收到自己的手牌、合法选择和公开场面，对方未知手牌仅传匿名数量。

一次操作采用「预演 → 双方完整展示 → 服务端提交一次 → 双方桌面稳定 → 后续触发／选择／胜利」。骰子窗口完全收起后才移动、摧毁或回手。触发逐项使用同一流程；没有先结算真实状态再补动画。客户端语言、设置和相机操作不进入规则命令。

展示阶段35秒、桌面结算阶段15秒的事务超时只计算双方均在线的时间。首次断线保存剩余时间，最后一方重连后恢复倒计时；恢复中的客户端必须重新确认当前阶段，旧回执不会重复提交规则。未开战或已结束的房间只剩一人且闲置10分钟后关闭；在线客户端收到房间失效提示，回到房间入口，服务器同时清理连接引用及检查点。

重连使用本机保存的房间座位凭证；这不是玩家账号。不要分享该凭证。服务端将私密检查点保存在 `/var/lib/illuminati-online/rooms`，目录权限700，记录不放入公开下载目录。服务重启恢复规则及完整64位随机状态；JSON还原时恢复规则整数，避免席位、命令和数组比较失真。

普通控制／摧毁声明会先定位带头者，再沿青绿／橙红箭头跟随到目标，以短文字标记类型；自动接管不播放攻击箭头。手牌招募以独立临时卡公开展示，成功后接入，失败后回手。临时卡不参与规则、胜利计数或控制线，重连可从公开战斗状态恢复。支援者与实际受支援者同时高亮并显示有效P／GP加值。上述演出全部在双方prepare屏障内完成，较快的一端也必须等待另一端，才能提交并开始下一响应计时。

## 运维

Godot 4.6.2 Linux无界面服务，由 `illuminati-online.service` 管理，内部只监听 `127.0.0.1:19081`，通过已有Nginx HTTPS入口代理WebSocket。无需额外开放公网端口。服务器发布与Windows补丁使用相同版本号、协议号及卡牌摘要校验，不同版本不能混局。

```powershell
python tools/export_online_server.py --godot <Godot控制台EXE>
python tools/deploy_online_server.py --host 47.119.37.251 --key <本机SSH私钥路径>
```

专用服务器从隔离的最小工程导出，不携带插画、字体、音效、客户端更新器或测试脚本。部署先校验上传大小和SHA-256，原子替换文件后重启服务；存在活跃对局时拒绝部署。更新清单发布后，同一版本禁止更换服务器字节。

```text
systemctl status illuminati-online.service
journalctl -u illuminati-online.service -n 60 --no-pager
```
